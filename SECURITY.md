# Security Policy

We take security and privacy seriously in this project.  
If you discover a vulnerability or potential security issue, please follow the responsible disclosure process described below.

---

## Reporting a Vulnerability

If you believe you’ve found a security vulnerability:

1. **Do not open a public GitHub issue.**  
2. Instead, please contact us directly at **[mdnaimhassansaykat@gmail.com](mailto:mdnaimhassansaykat@gmail.com)**.  
3. Include the following details (if available):
   - A clear description of the issue
   - Steps to reproduce the vulnerability
   - Any supporting code snippets or logs
   - The environment or configuration where it was found

We aim to acknowledge all valid reports within **72 hours** and to provide a fix or mitigation plan as soon as possible.

---

## Supported Versions

Security updates and patches are maintained for the **latest stable release** of this repository.  
Older versions may not receive security fixes unless explicitly noted in the release documentation.

| Version             | Supported       |
|----------------------|-----------------|
| Latest (main branch) | Yes (actively maintained) |
| Older releases       | No (unsupported) |

---

## Responsible Disclosure Guidelines

We kindly ask that you:

- Refrain from publicly disclosing the issue until a patch has been released.  
- Provide us with reasonable time to investigate and remediate the vulnerability.  
- Avoid sharing proof-of-concept exploits publicly.

Following these guidelines helps protect users, researchers, and collaborators while ensuring a coordinated and transparent fix process.
